TASK
Write a complete, runnable program that generates optimal solution to the Sequential 
Ordering Problem(SOP) instances from .sop files. This program should be able to 
find the optimal solution and be able to prove the result is optimal. This program
should be the most robust, state-of-the-art, time efficient program possible while
still finding the optimal solution. Include documentation that explains how to run the program 
and algorithmic descriptions, reasoning, and references.
This should be a complete, production-quality project with a deliberate, modular, readable 
architecture. 
NOTE: This should be the BEST SOP program you can create against any instance I provide
large or small instances, if you need me to respond for you to complete development due to rate or
context limits that works, I will respond until you complete the development of the program.

LANGUAGE AND ALGORITHM
The language and algorithms you use are your choice. Pick whichever will create
the best solution based on the TASK. However, this program will be run on ubuntu on an AMD Ryzen Threadripper 
2990WX (32 cores) with 122Gi of memory. Therefore, the final program MUST be parallelizable to take 
full advantage of the 32 cores.  Be aware of the NUMA topology this CPU uses. You must use the C++17 standard.

FILE FORMAT 
The file is TSPLIB-style: a metadata header, then the matrix, then an optional EOF.
- Header lines (NAME, TYPE, COMMENT, DIMENSION, EDGE_WEIGHT_TYPE, EDGE_WEIGHT_FORMAT)
  are metadata. Parse them by keyword. COMMENT is free text.
- DIMENSION is the number of nodes N. The input dimensions will be large so ensure 
  the program can handle that. N <= 1000
- EDGE_WEIGHT_SECTION is followed by N again, then N x N integers (a FULL_MATRIX)
  that may wrap across lines. The file may end with an EOF line, but not all
  instances have one. Do not depend on it: read exactly N x N values after the
  repeated dimension, and tolerate trailing blank lines or end-of-file with no
  terminator.
- Nodes are indexed 0..N-1 by matrix row/column order.

MATRIX SEMANTICS (T = the matrix)
- T[i][j] >= 0: cost of going directly from node i to node j.
- T[i][j] < 0: precedence constraint. Node i depends on node j, so j must come
  before i. The negative value is not a cost.
- The diagonal is 0 and is ignored.
- A very large value (e.g. 10000000) is just a large cost, typically the direct
  first-to-last edge, which a valid path never uses.

PROBLEM REQUIREMENTS
- Find a Hamiltonian path visiting every node exactly once and satisfying all
  precedence constraints.
- The start and end nodes are determined by the constraints. Derive them from the
  matrix, do not hardcode them. If there are multiple possible start and end nodes
  your algorithm must find which start and end nodes are optimal. 
- Minimize the sum of T[a][b] over consecutive nodes.

PROGRAM REQUIREMENTS
- Command-line use: accepts one .sop file, an optional time limit in
  seconds, an optional number of threads to use, an optional output CSV path,
  and an optional --no-header flag.
  Defaults: no time limit, single-threaded, print to stdout, header row included.
  ex. prog [filepath] [--time-limit SECONDS] [--threads N] [--output out.csv] [--no-header]
- Parse robustly (the matrix may span multiple lines).
- Include a validity check on the final path (permutation, precedence, cost
  recomputed from scratch).
- Report whether the solution is proven optimal or not.
- On a timeout report the best solution found and that it is not proven optimal. If no 
  feasible solution has been found set the Best Cost to -1, best path to empty, and optimal to no. 
- All logs should be sent to stderr to reduce stdout clutter. 
- When --output is given, write to the csv and to stdout, if the file exist append to it. 
- The header is only written when the file is new or empty unless --no-header is given. stdout always 
  gets a header unless --no-header is given.
- If you use an algorithm that tracks the current best cost, the program must log to stderr an update
  in the best known cost including the new cost.
- In-line comments. For each .cpp file that is written, include a summary at the top of each file that 
  explains the purpose of that file. Additional comments within the code should be focused on defining 
  the name of the algorithm and the specific part of the algorithm that part of the code performs. 

OUTPUT (CSV, one data row per run, preceded by a header row unless --no-header is given)
Instance,Instance Size,Time,Enumerated Nodes,Best Cost,Best Path,Optimal
- Instance: input file name
- Instance Size: N
- Time: total wall-clock seconds for the whole run on that instance, including the 
  optimality proof, or until timeout.
- Enumerated Nodes:  the sum of the number of nodes processed by each thread. If the 
  algorithm isn’t tree search, define the counted unit (e.g. DP states) in the README. 
  The total is summed across all threads.
- Best Cost: cost of the resulting path
- Best Path: node indices in order, space-separated, 0-based
- Optimal: yes only if optimality was proven before any time limit expired, 
  otherwise no.
